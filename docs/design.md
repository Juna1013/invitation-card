# 成人式後の同窓会 招待カードジェネレータ 設計書（CSV → HTMLコンポーネント → PNG）

## 1. 目的

名簿 CSV から、**Apple Wallet のパスのようなカード型の招待状 PNG を一人ずつ一括生成**するツール。

- カードは **HTML/CSS のコンポーネント**として作る（デザインをブラウザで確認しながら調整できる）
- 生成は**コマンド一発**で、ヘッドレスブラウザがカードを PNG に書き出す。生成用の UI は作らない
- デザインは**全カード共通で固定**。一人ごとに変わるのは氏名・当時のクラス・通し番号、クラスごとに変わるのは配色のみ

## 2. 要件

### 機能要件

| ID | 要件 | 優先度 |
|---|---|---|
| F1 | 名簿 CSV の1行につき1枚の PNG（透過）を出力する | Must |
| F2 | クラスごとに配色を割り当てる（9色のプリセット＋任意の色コード。教職員も1区分） | Must |
| F3 | どんな配色でも文字が読める（明るい色は濃色文字、暗い色は白文字に自動で切り替え） | Must |
| F4 | 通し番号を付与する（既定は行順に自動採番、CSV に列があればそれを優先） | Must |
| F5 | 入力不備を行番号付きで報告する（氏名/クラス欠落、番号重複、配色未割当のクラス） | Must |
| F6 | 長い氏名は縮小・折り返しで収め、収まらなければ警告 | Must |
| F7 | フォントに無い文字（旧字体・外字）を検出して警告 | Should |
| F8 | 割り当てた通し番号を CSV に書き戻せる（再生成時の番号ずれ防止） | Should |
| F9 | 一部の人・クラスだけ再生成できる | Could |

### 非機能要件

- 完全ローカル実行（個人情報を外部に送らない）
- フォントは同梱（環境非依存）、同じ入力から同じ PNG ができる
- デザイン調整用に、ブラウザでカード一覧を確認できる開発用プレビューを持つ（**生成機能のための UI ではなく、デザイン作業のための道具**）

### 対象外

生成用 Web UI、URL 共有、裏面フリップ、.ics、本物の Apple Wallet (.pkpass)

## 3. 入力の分担

| 入力 | 中身 | 粒度 |
|---|---|---|
| 名簿 CSV | 氏名・当時のクラス（＋任意で通し番号） | 1行 = 1人 = 1枚 |
| 設定ファイル（YAML） | カードに記載する文言（タイトル・サブタイトル・日付・開始/終了時刻・項目名・敬称）とクラス別の配色 | 全カード共通。**カードの文言はこの1ファイルだけで管理する** |

[card.yaml](../card.yaml)（例）：

```yaml
event:
  title: 勝田一中 同窓会
  subtitle: 令和3年度 卒業生一同
  date: "2027-01-11"               # 日時は1行で「2027.01.11 17:00 - 19:00」と表示
  start_time: "17:00"
  end_time: "19:00"
  venue: ホテルクリスタルパレス     # 会場名（カードの「場所」欄に表示）
  map_url: https://www.google.com/maps/search/?api=1&query=...   # 任意。画像にはリンクを埋め込めない。生成時に表示し、メール本文に貼る

labels:                            # 項目名と敬称
  guest_no: GUEST NO.
  recipient: 宛名
  datetime: 日時
  class: クラス
  venue: 場所
  honorific: 様                    # 宛名の末尾に付く

class_colors:                      # 当時のクラス（名簿の値）→ 配色（プリセット名 or #色コード）
  3年1組: 白練
  3年2組: 鬱金色
  3年3組: 常磐緑
  3年4組: 茜色
  3年5組: 蜜柑色
  3年6組: 藍色
  3年7組: 江戸紫
  3年8組: 撫子色
  教職員: 鉄黒

public_masks:                      # 公開用の画像で伏せる語句 → 置き換え後（省略可）
  勝田一中: 〇〇〇〇
```

- 読込と検証は [config.ts](../src/domain/config.ts)。必須項目の欠落・空文字・不明な配色は、不備をまとめて表示して停止する
- `map_url`（任意）は会場の地図リンク。**PNG にはクリックできるリンクを埋め込めない**ため、`npm run sample:pdf` で場所欄が `map_url` へのリンクになる PDF（500×740 px 相当の1ページ）を `samples/pdf/` に出力する。見た目は PNG と同じで、リンクは見た目に表れない。メールで画像として見せる場合は、メール本文に `map_url` を貼る
- `public_masks` は、SNS などに公開する画像で語句を伏せるための設定（省略可）。`npm run sample:public` と `npm run overview:public`（`--public`）のときだけ、タイトルとサブタイトルの語句を置き換える。通常の画像は変わらない。公開用の個別カードは `samples/public/cards/`（Git 管理外）、一覧画像は `samples/public/overview.png`（2040×3216 px。X の 4096 px 超の縮小を避けるため、通常の一覧画像より小さい）に出力する
- すべての文言は必須。日付は `YYYY-MM-DD`（存在する日付）、時刻は `HH:MM`（24 時間表記）で書く
- 日付の表示形式（`2027.01.11`）と通し番号の桁数（3 桁）は文言ではなくコード（[format.ts](../src/domain/format.ts)）で決める

### 名簿 CSV

サンプル：[samples/roster.sample.csv](../samples/roster.sample.csv)（架空の氏名 18 件、9クラス）。表記のゆれ・旧字体・長い氏名・全角スペースなどの確認用データを含む。

| 意味 | 受け付ける列名（例） | 必須 |
|---|---|---|
| 氏名 | `氏名` / `名前` / `name`（`姓`+`名` の別列なら結合）。氏名の列構成は未定のため両対応 | ○ |
| 当時のクラス | `当時のクラス` / `クラス` / `class` | ○ |
| 通し番号 | `ナンバー` / `番号` / `no` | |

- 通し番号は**全クラス通しで 001 から**。列が無ければ CSV の行順に自動採番
- 文字コードは UTF-8（BOM 可）と CP932（Excel 由来）を自動判別
- 氏名・クラスの前後の空白、全角/半角スペースは正規化
- ふりがなは扱わない

## 4. カードの設計（固定）

Apple Wallet のイベントパスの構成に合わせた1枚のカード。CSS サイズ 500×740 px（ハガキ比率）を **デバイスピクセル比 2.4** で書き出し、**1200×1776 px** の PNG にする。**角丸の外側は透過**（余白・影なし）。

```text
┌─────────────────────────────┐
│ 勝田一中 同窓会   GUEST NO.  │ ← ロゴ相当（タイトル）／通し番号
│ 令和3年度 卒業生一同    016    │
│ ◜ 麻の葉       ≋≋ ✿✿       │ ← 雲に花を添える（右上・左下の端から）
│  ◟                          │ ← 和傘（左上: 半分だけ顔を出す）
│          ◯ 渦               │ ← 和傘（中央: 丸ごと1つ）
│  ✿≋≋≋              ◜ 青海波  │ ← 和傘（右下: 半分だけ顔を出す）
├ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ┤
│ 宛名          日時           │ ← フッター（半透明の黒）
│ 〇〇 〇〇 様   2027.01.11 ...  │    等幅ラベル＋値。日時は
│ クラス        場所           │    「2027.01.11 17:00 - 19:00」を
│ 3年1組        ホテル…        │    1行・左揃えで表示。右下に場所
└─────────────────────────────┘
```

- **背景は無地**（クラスの配色を暗くした1色。グラデーションは使わない）に、**和傘と雲・花の線画（SVG）を文字色の透過で重ねる**。和傘は3つ：左上に「麻の葉」と右下に「青海波」を半分だけ顔を出させ、中央に「渦」を丸ごと1つ。**斜め一直線に等間隔（傘と傘のすき間は約41px）**に並べる。中央は半径125px、左上と右下はその0.9倍（半径112.5px。中心は変えない）。左上はヘッダーの下（上端 y=107.5）、右下はフッターの手前（下端 y=577.5）に収める。雲は右上・左下の端から入る2つ（左右対称にずらして、先端が内側を向く）。花は雲の下の段に重ねて添え、雲の上の段は見せる。ヘッダー・フッターの文字にかからない位置にする。線画なので、配色が変わっても形はそのまま
- **雲・花は自作の SVG**（[generate-ornament.ts](../scripts/generate-ornament.ts) → `src/assets/ornament/cloud-flowers.svg`）。いずれも幾何学的な図形から一から描き起こす。雲と花は傘より小さく（元の大きさの約78%。右は (500,104)、左は (0,565) を中心に縮小）、傘と重ならない余白を取る。霞は、横長の帯を4段、左右にずらして重ね、帯どうしを細くくびれた首でつないだ、**1本の閉じた輪郭線**（「工」「王」の字のような形。内側の線は引かない）。先端はきれいに丸い（すやり霞）。形の根拠は [JAANUS「kasumi」](https://projects.mcah.columbia.edu/jaanus/record/kasumi)（霞は「工」「王」の字のように様式化された横に広がる帯。13世紀以降、先端を丸く輪郭をくっきり描く）と、ユーザー提供の参照図。花は梅の線画を6種（二重の花びら、おしべの輪、放射状のおしべ、渦、涙形の印など）、右に9つ・左に8つ、雲の下の段に重ねる。花の下は SVG の mask で切り抜き、雲の線が花に透けず、手前の花が奥の花を隠す。既存サイトの画像のトレースやコピーはしない（公開リポジトリに載せるため）
- 和傘の素材の出典は `shikosai34/shikosai34-web`（和傘 SVG 3種。市松は未使用）。**ライセンス表記が無い**ため、利用は出典側の了承が前提（[src/assets/wagasa/README.md](../src/assets/wagasa/README.md)）
- **フッターは半透明**の黒のパネル。背景より一段暗くなり、文字の可読性が上がる
- ラベル・番号は等幅フォント（IBM Plex Mono）
- 氏名は長さに応じて縮小する（下限を超える場合は警告）
- 会場・返信期限・ひとことはカードに載せない（2026-11-22 に削除。必要になれば再追加）

### 配色

プリセット 9 色（名前は設定ファイルから参照）。日本の伝統色から選ぶ。1〜8組と教職員に1色ずつ。

| 名前 | 色 | 対象 | 文字・線画 |
|---|---|---|---|
| 白練（しろねり） | `#fcfaf2` | 1組 | 濃色 |
| 鬱金色（うこんいろ） | `#efbb24` | 2組 | 濃色 |
| 常磐緑（ときわみどり） | `#007b43` | 3組 | 白 |
| 茜色（あかねいろ） | `#b7282e` | 4組 | 白 |
| 蜜柑色（みかんいろ） | `#f08300` | 5組 | 濃色 |
| 藍色（あいいろ） | `#165e83` | 6組 | 白 |
| 江戸紫（えどむらさき） | `#745399` | 7組 | 白 |
| 撫子色（なでしこいろ） | `#dc9fb4` | 8組 | 濃色 |
| 鉄黒（てつぐろ） | `#281a14` | 教職員 | **金**（`#d4af37`） |

- 暗い色（常磐緑・茜色・藍色・江戸紫）は、白文字のコントラスト比が 4.8 以上あるため、地色を暗くする調整は入らず、指定の色のまま描画される
- 色名の選定理由：1組の白練は白との差がわずかで和紙の色味。桜色は白と区別できないため撫子色にした。黄（鬱金色）と橙（蜜柑色）、赤（茜色）は色相の差を保つ

- **明るい色**（濃色文字 `#111` とのコントラスト比が 6 以上）は、地色をそのまま使い、文字と線画を濃色にする。和傘の SVG は線の形だけを取り出し（CSS の mask）、文字色（`--ink`）で塗って透過で重ねる。元の SVG の線の色には依存しない
- **暗い色**は、文字と線画を白（鉄黒のカードだけ金）にする。その色のコントラスト比が 4.8 以上になる最小限の暗さまで地色を暗くする
- フッターは、暗い色では黒 30%、明るい色では黒 8% の半透明
- 計算結果は CSS カスタムプロパティ（`--card-bg` / `--ink` / `--footer-bg` / `--art-strength`）としてカードに注入するだけ（デザイン側は色を直接書かない）
- 任意の色コード（`#rrggbb`）も同じ規則で扱う

## 5. 技術構成

| 項目 | 採用 | 理由 |
|---|---|---|
| 実行環境 | Node.js 20+ / TypeScript | |
| コンポーネント | React（Preact でも可）＋ CSS（CSS 変数でテーマ注入） | 部品単位で管理でき、デザインの修正が容易 |
| 開発用プレビュー | Vite dev server | サンプル CSV のカード一覧をホットリロードで確認 |
| PNG 化 | Playwright（Chromium）で要素スクリーンショット、`omitBackground` で透過 | CSS の再現性が最も高い |
| CSV / YAML | `csv-parse` / `yaml`（導入済み）、文字コード判別に `iconv-lite` 等 | |
| フォント | Noto Sans JP・IBM Plex Mono（いずれも OFL）を同梱（`@fontsource`） | `document.fonts.ready` を待ってから撮影 |

### PNG 化の方式の比較

| 方式 | 利点 | 難点 |
|---|---|---|
| **Playwright（採用）** | ブラウザと同じ見た目。グラデーション・mask・blend など CSS をそのまま使える | Chromium（約150MB）の導入が必要、1枚あたり数百ms |
| Satori（JSX→SVG→PNG） | ブラウザ不要で軽い | 使える CSS が限定的（mask・blend などが不可）。凝った質感は不利 |
| Python + Pillow | 依存が少ない | デザインをコンポーネントで管理できない（今回の要望と合わない） |

### 構成

```text
invitation-card/
  package.json
  src/
    card/                     # 固定デザイン（ここだけがデザイン）
      Card.tsx                # props: { event, person, tokens }
      Card.css                # CSS 変数ベース
    domain/
      theme.ts                # 色導出・コントラスト計算・プリセット（純粋関数）
      format.ts               # 日付・時刻・通し番号の整形
      config.ts               # 設定ファイル（card.yaml）の読込・検証
      roster.ts               # 名簿CSV読込・列名の吸収・採番・検証
    cli/
      generate.ts             # エントリ: 読込 → 検証 → 撮影 → 保存
      browser.ts              # Playwright の起動・1枚ずつの撮影
    preview/                  # 開発用: サンプルCSVのカード一覧
  scripts/
    render-sample.ts          # サンプル PNG の生成
    render-overview.ts        # クラス別カードの一覧画像（3×3）の生成（npm run overview → samples/overview.png）。委員会などへの共有用。`--public` で語句を伏せた公開用（samples/public/overview.png）
    generate-ornament.ts      # 雲と花の SVG を生成（npm run ornament）
  src/assets/ornament/        # 雲と花（生成物）
  samples/roster.sample.csv
  docs/design.md
  out/                        # 出力（Git管理外）
```

設計上のルール：`Card` は `event`（共通情報）、`person`（1人分）、`tokens`（導出済みの色）だけを受け取る純粋な表示コンポーネントにする。「デザイン共通」を構造で保証する。

実行イメージ：`npm run generate -- roster.csv --config card.yaml -o out/`

## 6. 処理フロー

1. 設定ファイルと名簿 CSV を読み込み、列を判別
2. 全行を先に検証し、エラーは行番号付きでまとめて表示（1件でもあれば既定では生成しない）
3. ヘッドレスブラウザを1つ起動し、カードを描画するページを開く
4. 一人ずつ props を渡して描画 → フォント読込完了を待つ → カード要素を透過 PNG で保存
5. `out/<通し番号>_<クラス>_<氏名>.png` に保存し、件数と警告を表示

## 7. 個人情報の扱い

- 名簿 CSV と出力 PNG には氏名が含まれる。**`out/` と本物の名簿は Git 管理外**にする
- 外部サービスには送信しない（フォントも CDN を使わず同梱）
- リポジトリに置くサンプルは架空データのみ

## 8. リスク

| リスク | 対策 |
|---|---|
| 配色によって文字が読めない | 明るい色は濃色文字、暗い色は白文字に自動で切り替え（コントラスト比 4.8 以上） |
| 長い氏名で崩れる | 縮小・折り返し・下限超過の警告 |
| Excel 由来の文字化け | UTF-8 / CP932 の自動判別 |
| 旧字体・外字（髙、﨑 など）がフォントに無い | 撮影前に未収録文字を検出して警告 |
| フォント読込前に撮影して崩れる | `document.fonts.ready` と描画完了を待ってから撮影 |
| 通し番号が再生成でずれる | 番号を CSV に書き戻す機能（F8）。名簿の行順を変えない運用 |
| 透過の角に白フチが出る | 要素スクリーンショット＋`omitBackground`。初期に実機で確認 |

## 9. 決定事項

| 項目 | 決定 |
|---|---|
| 通し番号の採番順 | CSV の行順（全クラス通しで 001 から） |
| クラス表記 | 「3年1組」形式（配色の対応表のキー） |
| 配色の割り当て | 1組=白練、2組=鬱金色、3組=常磐緑、4組=茜色、5組=蜜柑色、6組=藍色、7組=江戸紫、8組=撫子色、教職員=鉄黒（2026-11-22 に和の伝統色へ変更。クラスは1〜8組＋教職員の計9区分） |
| 実行環境 | Node.js 20 以上、Chromium のダウンロード可 |
| 氏名の列 | 未定のため1列・姓名別列の両対応 |
| カードの構成 | Apple Wallet のイベントパス（ロゴ・GUEST NO.・下部の項目）に準拠。QR は一旦削除（2026-11-22）。背景は無地＋和傘・雲と花の線画、フッターは半透明。アクションタイル（返信期限・会場・幹事より）と柵は削除（柵は 2026-11-22 に削除） |
| カードのサイズ | 500×740 CSS px（ハガキ比率）→ 1200×1776 px |

実装に入る前に残っているのは、実データの CSV で列名が想定と異なる場合の調整のみ（設定ファイルで列名を指定できる設計）。
