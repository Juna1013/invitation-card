# 成人式後の同窓会 招待カードジェネレータ 設計書（CSV → HTMLコンポーネント → PNG）

## 1. 目的

名簿 CSV から、**Apple Wallet のパスのようなカード型の招待状 PNG を一人ずつ一括生成**するツール。

- カードは **HTML/CSS のコンポーネント**として作る（デザインをブラウザで確認しながら調整できる）
- 生成は**コマンド一発**で、ヘッドレスブラウザがカードを PNG に書き出す。生成用の UI は作らない
- デザインは**全カード共通で固定**。一人ごとに変わるのは氏名・当時のクラス・通し番号、クラスごとに変わるのは配色のみ

## 2. 要件

### 機能要件

| ID | 要件 | 優先度 |
|---|---|---|
| F1 | 名簿 CSV の1行につき1枚の PNG（透過）を出力する | Must |
| F2 | クラスごとに配色を割り当てる（9色のプリセット＋任意の色コード） | Must |
| F3 | どんな配色でも文字が読める（前景色を自動選択） | Must |
| F4 | 通し番号を付与する（既定は行順に自動採番、CSV に列があればそれを優先） | Must |
| F5 | 入力不備を行番号付きで報告する（氏名/クラス欠落、番号重複、配色未割当のクラス） | Must |
| F6 | 長い氏名は縮小・折り返しで収め、収まらなければ警告 | Must |
| F7 | フォントに無い文字（旧字体・外字）を検出して警告 | Should |
| F8 | 割り当てた通し番号を CSV に書き戻せる（再生成時の番号ずれ防止） | Should |
| F9 | 一部の人・クラスだけ再生成できる | Could |

### 非機能要件

- 完全ローカル実行（個人情報を外部に送らない）
- フォントは同梱（環境非依存）、同じ入力から同じ PNG ができる
- デザイン調整用に、ブラウザでカード一覧を確認できる開発用プレビューを持つ（**生成機能のための UI ではなく、デザイン作業のための道具**）

### 対象外

生成用 Web UI、URL 共有、裏面フリップ、QR、.ics、本物の Apple Wallet (.pkpass)

## 3. 入力の分担

| 入力 | 中身 | 粒度 |
|---|---|---|
| 名簿 CSV | 氏名・当時のクラス（＋任意で通し番号） | 1行 = 1人 = 1枚 |
| 設定ファイル（TOML） | 学校名・タイトル・開催年・日時・会場・会費・返信期限・ひとこと・クラス別の配色 | 全カード共通 |

```toml
# event.toml（例）
school    = "○○中学校"
title     = "成人式 同窓会"
year      = 2027
starts_at = "2027-01-11 18:00"
venue     = "ホテル○○ 2F 宴会場"
fee       = "5,000円"
deadline  = "2026-12-20"
message   = "久しぶりに、みんなで会いましょう！"

default_color = "空"

[class_colors]          # 当時のクラス → 配色（プリセット名 or #色コード）。クラス順にプリセットを割り当て
"3年1組" = "桜"
"3年2組" = "若草"
"3年3組" = "翡翠"
"3年4組" = "空"
"3年5組" = "藤"
"3年6組" = "朱"
"3年7組" = "紺"
"3年8組" = "金"
"3年9組" = "墨"
```

### 名簿 CSV

サンプル：[samples/roster.sample.csv](../samples/roster.sample.csv)（架空の氏名 18 件、9クラス）。表記のゆれ・旧字体・長い氏名・全角スペースなどの確認用データを含む。

| 意味 | 受け付ける列名（例） | 必須 |
|---|---|---|
| 氏名 | `氏名` / `名前` / `name`（`姓`+`名` の別列なら結合）。氏名の列構成は未定のため両対応 | ○ |
| 当時のクラス | `当時のクラス` / `クラス` / `class` | ○ |
| 通し番号 | `ナンバー` / `番号` / `no` | |

- 通し番号は**全クラス通しで 001 から**。列が無ければ CSV の行順に自動採番
- 文字コードは UTF-8（BOM 可）と CP932（Excel 由来）を自動判別
- 氏名・クラスの前後の空白、全角/半角スペースは正規化
- ふりがなは扱わない

## 4. カードの設計（固定）

縦型のハガキ比率（100×148mm）。CSS サイズ 500×740 px を **デバイスピクセル比 2.4** で書き出し、**1200×1776 px** の PNG にする。**角丸の外側は透過**（余白・影なし）。

```text
┌─────────────────────────────┐
│ INVITATION             2027 │
│  ┌───────────────────┐      │
│  │ 幾何学パターン       │      │
│  │ 成人式 同窓会        │      │ ← タイトル
│  └───────────────────┘      │
│  ○○中学校  3年2組            │
│  山田 太郎 様                │ ← 大見出し（宛名）
│ ◖┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄◗ │ ← 切り取り線（ノッチ）
│  日時            会場         │
│  1月11日(月) 18:00 ホテル…    │
│  会費            返信期限      │
│  5,000円         12月20日    │
│  ひとこと…           No. 012 │ ← 通し番号
└─────────────────────────────┘
```

- 角丸、斜めグラデーション、細いハイライト線で Wallet 風の質感を出す（CSS で表現）
- ノッチは `mask` で本当に切り抜き、背景の透過と両立させる

### 配色

プリセット 9 色（名前は設定ファイルから参照）。

| 名前 | 色 | 名前 | 色 | 名前 | 色 |
|---|---|---|---|---|---|
| 桜 | `#e8a0b4` | 空 | `#5b9bd5` | 紺 | `#1f3a5f` |
| 若草 | `#7db46c` | 藤 | `#8e7cc3` | 金 | `#c9a227` |
| 翡翠 | `#3aa38f` | 朱 | `#d9534f` | 墨 | `#2b2b2b` |

- 配色の色から、明るい側・暗い側のグラデーション端を計算し、**両端に対してコントラスト比が高い方（白 or 濃いグレー）を前景色**に採用。補助テキストは前景色の透過で表現
- 計算結果は CSS カスタムプロパティとしてカードに注入するだけ（デザイン側は色を直接書かない）
- 氏名は長さに応じて縮小し、下限を超える場合は2行折り返し、それでも収まらなければ警告

## 5. 技術構成

| 項目 | 採用 | 理由 |
|---|---|---|
| 実行環境 | Node.js 20+ / TypeScript | |
| コンポーネント | React（Preact でも可）＋ CSS（CSS 変数でテーマ注入） | 部品単位で管理でき、デザインの修正が容易 |
| 開発用プレビュー | Vite dev server | サンプル CSV のカード一覧をホットリロードで確認 |
| PNG 化 | Playwright（Chromium）で要素スクリーンショット、`omitBackground` で透過 | CSS の再現性が最も高い |
| CSV / TOML | `csv-parse` / `smol-toml`、文字コード判別に `iconv-lite` 等 | |
| フォント | Noto Sans JP（OFL）を同梱（`@fontsource` 等） | `document.fonts.ready` を待ってから撮影 |

### PNG 化の方式の比較

| 方式 | 利点 | 難点 |
|---|---|---|
| **Playwright（採用）** | ブラウザと同じ見た目。グラデーション・mask・blend など CSS をそのまま使える | Chromium（約150MB）の導入が必要、1枚あたり数百ms |
| Satori（JSX→SVG→PNG） | ブラウザ不要で軽い | 使える CSS が限定的（mask・blend などが不可）。凝った質感は不利 |
| Python + Pillow | 依存が少ない | デザインをコンポーネントで管理できない（今回の要望と合わない） |

### 構成

```text
invitation-card/
  package.json
  src/
    card/                     # 固定デザイン（ここだけがデザイン）
      Card.tsx                # props: { event, person, theme }
      Card.css                # CSS 変数ベース
      parts/                  # Header / Strip / Recipient / InfoField / Footer など
    domain/
      theme.ts                # 色導出・コントラスト計算・プリセット（純粋関数）
      config.ts               # 設定ファイル読込・検証
      roster.ts               # 名簿CSV読込・列名の吸収・採番・検証
    cli/
      generate.ts             # エントリ: 読込 → 検証 → 撮影 → 保存
      browser.ts              # Playwright の起動・1枚ずつの撮影
    preview/                  # 開発用: サンプルCSVのカード一覧
  samples/roster.sample.csv
  docs/design.md
  out/                        # 出力（Git管理外）
```

設計上のルール：`Card` は `event`（共通情報）、`person`（1人分）、`theme`（導出済みの色）だけを受け取る純粋な表示コンポーネントにする。「デザイン共通」を構造で保証する。

実行イメージ：`npm run generate -- roster.csv --config event.toml -o out/`

## 6. 処理フロー

1. 設定ファイルと名簿 CSV を読み込み、列を判別
2. 全行を先に検証し、エラーは行番号付きでまとめて表示（1件でもあれば既定では生成しない）
3. ヘッドレスブラウザを1つ起動し、カードを描画するページを開く
4. 一人ずつ props を渡して描画 → フォント読込完了を待つ → カード要素を透過 PNG で保存
5. `out/<通し番号>_<クラス>_<氏名>.png` に保存し、件数と警告を表示

## 7. 個人情報の扱い

- 名簿 CSV と出力 PNG には氏名が含まれる。**`out/` と本物の名簿は Git 管理外**にする
- 外部サービスには送信しない（フォントも CDN を使わず同梱）
- リポジトリに置くサンプルは架空データのみ

## 8. リスク

| リスク | 対策 |
|---|---|
| 配色によって文字が読めない | 前景色の自動選択＋コントラスト警告 |
| 長い氏名で崩れる | 縮小・折り返し・下限超過の警告 |
| Excel 由来の文字化け | UTF-8 / CP932 の自動判別 |
| 旧字体・外字（髙、﨑 など）がフォントに無い | 撮影前に未収録文字を検出して警告 |
| フォント読込前に撮影して崩れる | `document.fonts.ready` と描画完了を待ってから撮影 |
| 通し番号が再生成でずれる | 番号を CSV に書き戻す機能（F8）。名簿の行順を変えない運用 |
| 透過の角に白フチが出る | 要素スクリーンショット＋`omitBackground`。初期に実機で確認 |

## 9. 決定事項

| 項目 | 決定 |
|---|---|
| 通し番号の採番順 | CSV の行順（全クラス通しで 001 から） |
| クラス表記 | 「3年1組」形式（配色の対応表のキー） |
| 配色の割り当て | クラス順に 桜→若草→翡翠→空→藤→朱→紺→金→墨（1組〜9組） |
| 実行環境 | Node.js 20 以上、Chromium のダウンロード可 |
| 氏名の列 | 未定のため1列・姓名別列の両対応 |

実装に入る前に残っているのは、実データの CSV で列名が想定と異なる場合の調整のみ（設定ファイルで列名を指定できる設計）。
